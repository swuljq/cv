# ClipBridge 剪贴板共享软件需求文档（PRD）

- **文档状态**：第一版草案
- **版本**：0.1
- **日期**：2026-10-01
- **项目代号**：ClipBridge
- **目标平台**：Android、Linux、Windows
- **服务端部署**：用户自有服务器，用于账号认证、设备管理和内容中转

## 1. 背景与目标

用户在多台设备之间复制文本或图片时，需要通过即时通讯、网盘或手动文件传输完成中转，操作成本高且容易泄露内容。ClipBridge 提供一个跨平台剪贴板同步工具：用户在设备上登录同一个账号后，任一已登录设备复制的文本或图片会同步到其他在线设备的剪贴板。

第一阶段只支持一个固定账号，目的是先验证核心同步链路和跨平台体验。账号数量、团队协作和复杂权限在后续版本处理。

## 2. 产品目标

### 2.1 必须达到

1. Android、Linux、Windows 客户端能够登录同一个账号。
2. 任一设备复制文本后，其他在线设备能在可接受延迟内收到并写入系统剪贴板。
3. 任一设备复制图片后，其他在线设备能收到并写入系统剪贴板。
4. 用户自有服务器只承担认证、设备连接和内容中转，不要求客户端之间能够直连。
5. 同一内容不会因为同步写回而在设备之间无限循环。
6. 断网期间不崩溃；恢复网络后能够按明确规则补发或放弃离线内容。

### 2.2 暂不支持

- 多账号、注册、找回密码、组织和权限管理
- 文件、富文本、HTML、剪贴板历史搜索
- 端到端加密之外的复杂密钥托管体系
- 点对点传输、局域网自动发现
- 多人共享空间、公开分享链接
- 自动 OCR、格式转换和图片编辑

## 3. 典型用户场景

### 场景 A：电脑复制到手机

用户在 Windows 或 Linux 电脑复制一段文本，Android 设备在网络正常且登录同一账号时收到同步内容，用户在手机任意输入框中粘贴即可使用。

### 场景 B：手机拍照后传到电脑

用户在 Android 中复制一张图片，桌面端收到图片并写入系统剪贴板，用户可以直接在编辑器或聊天软件中粘贴。

### 场景 C：短暂断网

设备离线期间用户继续复制内容。网络恢复后，客户端按照“最新内容优先”的策略发送仍在本地队列中的项目；超过保存期限的项目自动丢弃并记录本地日志。

### 场景 D：多台设备同时复制

服务端为每条剪贴板事件分配全局事件 ID 和服务端时间戳。客户端按事件顺序处理；默认采用最后写入者获胜，后到事件覆盖先到事件。

## 4. 用户与设备模型

### 4.1 账号模型（MVP）

- 系统预置一个账号，账号标识和密码由部署者通过服务端环境变量配置。
- 客户端使用账号标识和密码登录，服务端返回短期访问令牌和刷新令牌。
- 不提供公开注册页面。
- 服务端不得在日志中记录明文密码或访问令牌。

### 4.2 设备模型

每次登录生成一个设备记录，至少包含：

- `device_id`：随机生成、稳定保存于本机
- `device_name`：用户可编辑名称
- `platform`：`android`、`linux`、`windows`
- `app_version`
- `last_seen_at`
- `online`

MVP 允许同一账号绑定多个设备。用户可以在客户端查看设备列表并撤销某个设备的令牌。

## 5. 核心功能需求

### 5.1 登录与会话

- 支持账号标识、密码输入和登录状态保存。
- 登录失败时显示明确但不泄露账号是否存在的错误信息。
- 访问令牌过期后自动刷新；刷新失败时回到登录页。
- 支持退出登录，并清理本地令牌和待发送队列中的敏感内容。

### 5.2 剪贴板监听

- 文本：监听系统剪贴板变化，读取纯文本内容。
- 图片：监听系统剪贴板变化，读取位图或平台可转换为位图的数据。
- 空内容、超过大小限制的内容和不支持的格式必须被忽略并记录原因。
- 客户端写入同步内容后必须标记来源，避免再次作为新事件上传。
- 用户可以暂停同步、恢复同步，并可设置“仅在 Wi-Fi 下同步图片”。

### 5.3 内容同步

每条同步事件至少包含：

```json
{
  "event_id": "uuid",
  "device_id": "uuid",
  "type": "text | image",
  "created_at": "RFC3339",
  "content_hash": "sha256",
  "text": "...",
  "image": {
    "mime_type": "image/png",
    "width": 1920,
    "height": 1080,
    "size_bytes": 123456,
    "data": "base64 or binary upload reference"
  }
}
```

- 文本直接通过 WebSocket 消息传输；图片使用分片或独立上传接口，避免单条 WebSocket 消息过大。
- 服务端将事件转发给除来源设备外的同账号在线设备。
- 客户端收到事件后发送确认；服务端在有限期限内保留未确认事件。
- 重复事件按 `event_id` 去重；同内容可通过 `content_hash` 避免重复传输。

### 5.4 本地状态与历史

- MVP 只保留最近 N 条待发送事件，默认 N=20。
- 默认本地不展示剪贴板历史；只保留同步所需的短期队列。
- 图片和文本的本地缓存必须提供清理策略，并在退出登录时删除。
- 后续版本可增加用户可见的历史列表和手动重新复制。

### 5.5 设置

- 同步总开关
- 图片同步开关
- 图片最大大小
- 是否仅在 Wi-Fi 下同步图片（Android）
- 设备名称
- 服务端地址
- 退出登录

## 6. 平台要求

### 6.1 Android

- 使用前台服务或系统允许的后台机制维持剪贴板同步；必须展示常驻通知并解释用途。
- 首次启用时说明 Android 对后台剪贴板访问的限制，并引导用户完成必要设置。
- 适配 Android 10 及以上版本；最低版本可在技术设计阶段确认。
- 图片写入系统剪贴板后，应用进入后台时仍需保持稳定。
- 处理 Doze、省电策略、网络切换和进程被系统回收。

### 6.2 Windows

- 使用系统剪贴板监听机制监听变化。
- 客户端可最小化到托盘并在后台运行。
- 退出应用时应停止监听并断开连接。
- 支持 Windows 10 及以上版本；Windows 11 为主要验证环境。

### 6.3 Linux

- 首版优先支持 X11，并明确 Wayland 的支持状态。
- 对 Wayland：若系统权限或桌面环境限制剪贴板监听，客户端必须显示原因和替代操作。
- 支持常见桌面环境（GNOME、KDE）中的文本和图片剪贴板。
- 提供命令行日志开关，方便用户排查桌面环境差异。

## 7. 服务端需求

### 7.1 服务端组件

1. **API 服务**：账号登录、令牌刷新、设备管理、健康检查。
2. **同步网关**：WebSocket 长连接、事件转发、确认和重连。
3. **内容暂存层**：图片临时对象存储或本地磁盘，配置保留期限。
4. **持久化层**：保存账号、设备、事件元数据和撤销令牌；可以从 SQLite 起步。
5. **运维配置**：监听地址、域名、TLS、账号密码、图片大小、保留时间均通过环境变量或配置文件设置。

### 7.2 建议接口

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `POST /api/v1/auth/logout`
- `GET /api/v1/devices`
- `DELETE /api/v1/devices/{device_id}`
- `GET /api/v1/health`
- `GET /api/v1/sync`：升级为 WebSocket
- `POST /api/v1/blobs`：图片分片上传
- `GET /api/v1/blobs/{blob_id}`：图片读取

### 7.3 连接与重连

- 客户端启动后自动连接服务端。
- 断开后采用指数退避重连，最大间隔默认 60 秒。
- 网络恢复后先刷新令牌，再发送本地待发送队列。
- 服务端必须限制单账号设备数量、连接频率、单事件大小和图片总存储量，具体默认值在技术设计中确定。

## 8. 安全与隐私

- 所有生产环境通信必须使用 HTTPS/WSS。
- 密码在服务端使用 Argon2id 或同等级别算法存储哈希。
- 访问令牌短期有效，刷新令牌可撤销并绑定设备。
- 图片临时对象使用随机不可预测 ID，不暴露真实文件名。
- 服务端默认不永久保存剪贴板内容；事件和图片按保留期限自动删除。
- 日志不得记录文本正文、图片内容、密码、令牌或完整请求体。
- 客户端界面应明确提示“复制内容会被发送到自有服务器并同步到已登录设备”。
- 用户删除设备或退出账号后，服务端应拒绝该设备继续接收事件。

## 9. 非功能需求

### 9.1 性能

- 文本事件在正常网络下端到端同步延迟目标：P95 ≤ 2 秒。
- 1 MB 以内图片在正常网络下同步完成目标：P95 ≤ 10 秒。
- 客户端空闲时 CPU 和内存占用应适合常驻运行。

### 9.2 可用性

- 服务端重启后客户端可自动恢复连接。
- 单个异常事件不得导致同步线程退出。
- 客户端必须提供可读日志和最近一次错误状态。

### 9.3 可观测性

- 服务端记录连接数、认证失败数、事件数、转发失败数、图片大小分布和延迟分位数。
- 日志采用结构化格式，支持按 `request_id`、`device_id`、`event_id` 排查。
- 提供不包含敏感内容的健康检查接口。

## 10. 事件顺序与冲突规则

- 服务端接收时间作为全局排序依据，客户端创建时间用于展示和诊断。
- 同一事件重复到达时只处理一次。
- 多台设备同时复制时，最后被服务端接受的事件覆盖之前事件。
- 来源设备默认不再写回自己的剪贴板。
- 客户端写入同步内容后产生的系统剪贴板通知必须被忽略，防止回环。
- 断线期间的离线队列按先进先出发送，但服务端可以根据事件过期时间丢弃旧事件。

## 11. MVP 验收标准

### 登录与设备

- [ ] 使用配置好的唯一账号可以在三类平台登录。
- [ ] 错误密码不会登录，且不会泄露敏感信息。
- [ ] 同一账号的多个设备能在设备列表中看到并可撤销。

### 文本同步

- [ ] Windows → Linux、Linux → Windows、Android → Windows、Windows → Android 四个方向均可同步文本。
- [ ] 同步文本在目标设备可以被系统其他应用粘贴。
- [ ] 同一事件不会形成循环复制。

### 图片同步

- [ ] Windows、Linux、Android 之间至少完成双向图片同步。
- [ ] 超过大小限制的图片被拒绝并有可读提示。
- [ ] 图片同步失败不会影响后续文本同步。

### 网络与安全

- [ ] 断网期间客户端不崩溃，恢复网络后按规则重连。
- [ ] 生产配置使用 HTTPS/WSS。
- [ ] 服务端日志不包含剪贴板正文和令牌。
- [ ] 退出登录后设备不能继续接收同步事件。

## 12. 交付阶段

### 阶段 0：技术验证

验证三类平台的剪贴板监听和写回能力，确认 Android 后台限制、Linux Wayland 能力和统一客户端框架。

### 阶段 1：MVP

完成唯一账号、设备登录、文本同步、图片同步、服务端中转、重连和基础设置。

### 阶段 2：可用性完善

增加安装包、自动更新或发布流程、日志导出、设备管理、存储清理、更多 Linux 桌面环境适配。

### 阶段 3：扩展能力

评估多账号、端到端加密、剪贴板历史、局域网直连、更多内容类型和团队共享空间。

## 13. 待确认事项

以下内容不阻塞需求文档第一版，但会影响技术设计和排期：

1. 客户端统一技术栈：Flutter、Qt、Tauri 或分别使用原生技术。
2. 服务端语言和部署方式：Docker、裸机服务或现有服务器框架。
3. 图片单项大小、总存储量和服务端保留时间。
4. Linux 是否必须支持 Wayland，还是首版只支持 X11。
5. Android 最低版本及是否接受常驻前台通知。
6. 是否需要端到端加密，还是首版使用 TLS 加密传输并由服务端临时中转。
7. 离线队列是否需要跨客户端保留，还是只保留在产生事件的设备上。
8. “一个账号”是固定账号密码，还是首版使用一次性邀请码/预置密钥。

## 14. 技术决策建议（草案）

在没有额外约束的情况下，建议先采用：

- 客户端：Flutter，统一 Android、Windows、Linux UI 和业务层；平台剪贴板监听通过插件或少量原生代码补齐。
- 服务端：Go，提供 HTTPS、WebSocket、SQLite/外部数据库和图片暂存能力，便于部署到自有服务器。
- 同步协议：REST 负责认证和设备管理，WebSocket 负责文本事件、确认和在线状态，HTTP 分片接口负责图片。
- 部署：Docker Compose，包含服务端、数据库和可选的对象存储目录。
- 第一版安全边界：TLS + 短期 JWT/刷新令牌 + 服务端短期暂存；端到端加密作为后续方案评估。

该建议需要在技术设计阶段结合服务器系统、域名/TLS 条件和用户对 Wayland、Android 后台运行的要求最终确定。
